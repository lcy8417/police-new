# 배치 — 화면 폭 · 스크롤 잘림 방지 · 좌표 민감 영역

**결론: 1280px 이상이 기준 지원 폭이고(시안 1440px 배치가 늘고 줄어듦), 1024~1279px는 축소 배치, 1024px 미만은 범위 밖이다. 부품은 부모 폭을 따르는 유동형으로 만들고, 어느 폭에서 배치를 바꿀지는 화면이 정한다. 콘텐츠가 스크롤 없이 잘리면 안 된다. 그리고 문양추출 캔버스처럼 사진 크기를 재서 서버로 좌표를 보내는 곳은 공용 부품으로 감싸지 않는다.**

## 화면 폭별 배치 (2026-11-13 사용자 결정 — 「반응형으로」)

감정관 PC의 해상도를 모르므로 폭 구간과 바뀌는 것을 여기서 정한다. Tailwind는 폭별 규칙을 적게 해 줄 뿐 자동으로 반응형이 되지 않는다.

| 폭 | 대상 | 모양 |
|---|---|---|
| 1920px 이상 | 일반 사무용 모니터 | 시안 배치 그대로, 남는 폭은 양옆 여백(본문 최대 폭은 정해지면 `tokens.md`에) |
| **1280~1919px (`xl`)** | 노트북 · 125% 확대 | **기준 지원 범위** — 시안 1440px 배치가 늘고 줄어듦. 넓은 목록(DataGrid)은 **표 안에서만** 가로 스크롤 |
| 1024~1279px (`lg`) | 작은 노트북 · 150% 확대 | 축소 배치: 사이드바 접힘 · 검색 폼 3열 → 2열 · 큰 팝업은 화면 가득 |
| 1024px 미만 | 태블릿 · 폰 | **범위 밖** — 「더 넓은 화면에서 사용해 주세요」 안내 |

읽는 법: 창 폭이 속한 줄의 「모양」대로 보여야 한다. 폭 기준은 `lg`(1024) · `xl`(1280) 두 개만 쓴다.

- **부품은 유동형** — 부모 폭에 맞춰 늘고 줄며 `min-w-0`(글자가 길어도 부모를 밀어내지 않게). 고정 폭은 사진 틀 · 아이콘 · 숫자 칸처럼 꼭 필요한 곳만(예: Field `search-shell` 260px).
- **폭별 바꿈은 화면(pages · widgets)이 정한다** — 공용 부품 안에 `lg:` · `xl:` 배치 규칙을 넣지 않는다.
- 축소 배치(1024~1279)는 시안에 없는 모양이므로 **시안에 먼저 그려 승인**받는다.
- 확인: 모양 대조는 시안 기준 폭 **1440**에서, 배치 확인은 **1024 · 1280 · 1440 · 1920** 네 폭 캡처에서 잘림 · 넘침 · 겹침 0.
  - 지금 자동 확인(`tests/ui/responsive.spec.ts`)은 진열 화면 조립 예시(`/dev/parts?view=example`)를 본다. 조립 예시는 **시안 복사본이 아니라** S01 검색 조건 패널 · S02 모달 머리 띠와 채취 방법 한 줄을 대표 부품 6개로 **다시 짠 것**이다(자동 대조 대상 아님). 폭마다 조립 예시 · `main` · 문서 가로 넘침 없음, 같은 부모의 형제 부품 겹침 없음(형제 묶음이 1개 이상 있어야 함), 부모 밖 삐져나감 없음을 보고, 폭마다 캡처 한 장을 결과물로 붙인다(기준 이미지 아님).
- 감정관 PC의 실제 해상도 · 확대율은 경찰청 확인 목록에 있다. 답이 오면 이 표만 고친다.

## 스크롤 잘림 방지

**결론: 어떤 폭 · 높이에서도 콘텐츠가 스크롤 없이 잘리면 안 된다.** 이 앱은 `html` · `body` · `#root`가 `overflow: hidden`이라 화면마다 자기 스크롤 상자가 있어야 한다.

| 자리 | 이렇게 |
|---|---|
| 세로 틀(`flex flex-col`)의 스크롤 자식 | `flex-1 min-h-0 overflow-y-auto` — `min-h-0`이 없으면 자식이 내용 높이만큼 자라 부모를 넘치고 스크롤이 생기지 않는다 |
| 머리 · 발(버튼 줄 등) | `shrink-0` — 줄어들지 않고 본문만 스크롤 |
| 높이 % (`h-full`) | 부모 높이가 확정일 때만 동작한다. 중간에 높이가 `auto`인 칸이 끼면 깨지므로 위에서부터 `flex-1 min-h-0`으로 잇는다 |
| 넓은 표(DataGrid) | 표를 감싼 상자에서만 `overflow-x-auto`. 화면 전체에 가로 스크롤을 만들지 않는다 |
| `overflow-hidden` | 장식을 자를 때만(모서리 둥글림 등). 내용을 숨기려고 쓰지 않는다 |

읽는 법: 스크롤이 필요한 칸을 만들 때 왼쪽 자리에 해당하는 줄을 모두 지킨다.

- 스크롤 막대 모양은 `src/index.css`의 전역 규약(얇고 투명한 트랙 · line 색 막대) 그대로 둔다.

## 좌표 민감 영역 — 공용 부품으로 감싸지 않는다

**결론: 표시된 이미지의 크기(`getBoundingClientRect`)를 재서 서버로 좌표를 보내는 곳은, 그 `<img>` · `<canvas>`와 부모의 크기 · 맞춤 방식 · 감싼 구조를 바꾸지 않는다. 바꾸면 문양추출 좌표가 어긋나 서버가 422 · 500으로 실패한다(실제 사고 — `docs/api-communication.md` §4).**

| 대상 | 무엇을 재나 |
|---|---|
| `src/features/patterns-extract/ui/PatternCanvas` | 경계선 y좌표 · 캔버스 크기(`line_ys` · `render_size`) |
| `src/hooks/useCalibration.js` | 4점 각도 보정 좌표 |
| `src/components/Canvas.jsx` | 자르기 · 회전 |
| 정렬 · 대응점 편집 화면 | 대응점 좌표 |

읽는 법: 위 파일과, 같은 방식으로 사진 크기를 재서 좌표를 보내는 모든 곳이 대상이다. 이 파일들의 좌표 수학 · 크기 규칙은 **수정 금지**.

- `viewer` 부품은 여기서 **잰 요소 밖에 얹는 `pointer-events-none` 겹 장식**으로만 쓴다(누름 · 끌기 판정을 막지 않게).
- 시안 사진은 일부가 잘리는 방식(`preserveAspectRatio="xMidYMid slice"`)이지만 캔버스는 전체를 담는 방식(`object-contain`)이다 → **캔버스 화면에는 시안의 잘린 틀을 적용하지 않는다.**
- 래퍼 `div`를 만드는 부품(예: `LoadingImage`)은 캔버스류에 쓰지 않는다. `viewer` 부품마다 이 주의를 주석으로 단다. 이미지 로딩 표시는 기존 `relative` 상자 안에 형제로 얹는 `ImageLoadingOverlay`를 쓴다.
- 확대경 · 십자선 · 자르기 · 회전 · 대응점 **편집**은 공용화하지 않는다. 필요한 화면에서 좌표 계약을 확인한 뒤 그 화면에서 추출한다.
