# 족적 감정 플랫폼 화면 디자인 정본

**결론: 화면의 생김새는 이 스킬이 기준이다. 부품은 `@/shared/ui/` 아래 출입구 4개(`kit` · `viewer` · `ai` · `panel`)에서만 꺼내 쓰고, 목록에 없는 부품은 「목록에서 찾기 → 시안에 먼저 그림 → 상태별 실제 스타일값 읽기 → 토큰으로 옮기기 → 자동 대조 → 목록에 한 줄」 순서로만 늘린다. 색은 토큰 이름만 쓰고 hex(`#0b121d` 같은 색 번호)는 새로 쓰지 않는다. 고친 뒤에는 `npm run check:ui`가 통과해야 한다.**

이 파일은 설계서 `docs/superpowers/specs/2026-11-13-ui-parts-sot-design.md`의 §2(우선순위) · §8(늘리는 순서) · §11(원칙 · 하지 말 것 · 갱신 절차)을 옮겨 적은 **정본**이다. 앞으로 바꿀 일이 생기면 이 스킬을 고친다. 설계서는 만들 때의 판단을 남긴 **기록 문서**로 두고 다시 고치지 않는다.

## 용어 (처음 한 번만 풀이)

- **정본(SOT, Source of Truth)**: "이 주제는 여기가 기준"인 단 하나의 자리. 다른 문서 · 코드는 가리키기만 한다.
- **시안**: 사용자가 승인한 화면 그림 r3, `docs/mockups/scas-redesign/`. `index.html`을 브라우저로 열면 화면 16개(S00 로그인 … S15 모델 관리)가 나온다. **생김새의 원본**이다.
- **부품(컴포넌트)**: 여러 화면에서 다시 쓰는 화면 조각(버튼 · 칩 · 패널 …). **출입구(배럴)**: 부품을 한곳에서 내보내는 `index.ts` 파일.
- **토큰**: 색 · 크기에 붙인 이름(`--t-panel`, Tailwind `bg-panel`). 화면 코드는 값 대신 이 이름을 쓴다.
- **계산값(computed style)**: 브라우저가 최종으로 적용한 실제 스타일값. 눈대중 대신 이 값을 읽는다.
- **변형(variant)**: 같은 부품의 승인된 다른 모양(예: 버튼 `sm-pri`). **상태**: 같은 변형이 놓이는 처지(예: 잠김 `locked`).
- **표식**: 시안 · 앱 요소에 붙이는 속성 `data-part`(부품) · `data-part-variant`(변형) · `data-part-state`(상태) · `data-part-id`(대조 짝 번호, 형식 `S01-03`). `data-state`는 shadcn(이 앱이 쓰는 기본 부품 모음)이 이미 쓰므로 **쓰지 않는다**.
- **부품표(`parts-plan.md`)**: 시안 · 진열 화면을 고치기 전에 "어느 자리에 어느 부품을 쓰나"를 적는 표. **훅(hook)**: 파일을 쓰기 직전에 자동으로 도는 검사. 부품표가 틀리면 쓰기를 막는다.
- **진열 화면**: 구현된 부품만 변형 × 상태로 늘어놓은 개발용 화면 `/dev/parts`(`src/pages/dev/parts/`, 개발 실행에서만 열림).

## 언제 이 스킬을 여나

| 하는 일 | 열어야 하나 |
|---|---|
| 색 · 글꼴 · 굵기 · 간격 · 모서리 · 그림자 · 배치 · 상태 표시 중 하나라도 바꿈 | **연다** — 참고 파일까지 |
| 시안(`docs/mockups/scas-redesign/`) · 진열 화면(`src/pages/dev/`)을 고침 | **연다** — 부품표도 먼저(아래 작업 순서 0) |
| 생김새와 상관없는 로직 · 데이터만 고침 | 안 열어도 된다 |

읽는 법: 왼쪽에 해당하는 일이 하나라도 있으면 오른쪽대로 한다.

## 무엇이 먼저인가 — 우선순위

**사용자 말 > 이 스킬의 `references/`(사용자 승인 기록이 있는 항목만 시안보다 앞섬) > r3 시안의 계산값 > 지금 앱 코드.**

1. **r3 시안이 생김새의 승인 원본**이다(2026-11-13 사용자). 값이 헷갈리면 시안을 띄워 계산값을 뽑는다. 지금 앱 코드의 모양을 기준으로 삼지 않는다.
2. **romang(다른 프로젝트 `~/Desktop/romang`)의 디자인 체계를 골라서 따랐다**: 정본 = 스킬, 규칙 파일은 방아쇠, 부품 목록 표, 없으면 만드는 순서, 부품표 관문, 자동 대조, 하지 말 것 기록. romang의 색 · 글꼴 · 세무 화면 취향은 옮기지 않았다. **"romang 그대로"가 아니라 이 스킬에 적힌 것만** 따른다.
3. 설계서는 Codex(다른 AI)의 교차 검증을 거쳐 확정됐다(r2).

## 부품은 출입구 4개에서 꺼낸다

**결론: 업무를 모르는 부품만 `src/shared/ui/` 아래 출입구 4개에 둔다. 업무 말 · 판정 · 권한 · 세션은 `entities` · `features` · `widgets`에 남긴다.**

| 출입구 | 담는 것 | 넣어도 되나 묻는 질문 |
|---|---|---|
| `@/shared/ui/kit` | 버튼 · 입력 · 고르기(검색형 포함) · 탭 · 칩 · 꼬리표 · 툴팁 · 대화상자 틀 · 표 · 쪽수 · 안내 줄 | 족적이 아닌 앱에서도 뜻이 통하나? |
| `@/shared/ui/viewer` | 족적 사진 **표시** — 사진 틀 · 보기 방식(원본 · 이진화 · 반전 · 대비) · 증거 꼬리표 · 자 · 비교 보기 · 상중하 띠 · 히트맵 · 대응점 **그림** | 사진 위에 무언가를 **보여 주나**? (재는 건 아님) |
| `@/shared/ui/ai` | AI 꼬리표 · 진행 막대 · 훑기 효과 · 실시간 점 · 신뢰도 막대 · 숫자 타일 · 점검표 · AI 제안 카드 | AI가 했다 · 하는 중 · 얼마나 확신하는지를 보여 주나? |
| `@/shared/ui/panel` | SCAS 틀의 **배치 껍데기** — 메뉴 · 사용자 · 탭 목록을 **받아서** 그리는 위 메뉴 · 탭 줄, 검색 조건 패널, 버튼 줄, 라벨-값 폼, 단계 띠, 위치 표시, 쪽 머리 | SCAS(지금 경찰이 쓰는 시스템) 화면 배치를 재현하나? (업무 말 · 권한 판단 없음) |

읽는 법: 새 부품을 어디 둘지 모르면 위에서부터 「질문」에 답해 처음 "예"인 출입구에 둔다. 어디에도 "예"가 아니면 공용 부품이 아니다.

- **가져오기 규칙(ESLint가 검사)**: `pages` · `widgets` · `features` · `entities`는 위 4개 출입구로만 가져온다. `@/shared/ui` 루트, `@/shared/ui/<shadcn 파일>`, `@/shared/ui/kit/<파일>`처럼 안쪽을 직접 가져오면 **오류**다. 예외는 기존 파일 목록 `scripts/ui/ui-legacy.txt`(부품 작업 직전 커밋 d6987ae에 있던 파일, 233개)뿐으로 이 파일들만 **경고**. 새 파일은 목록에 더하지 않는다 — 만드는 순간 오류 규칙을 받는다. 화면을 옮겨 끝낸 파일은 전환 완료 목록 `scripts/ui/ui-converted.txt`에 올린다(레거시 목록에 있어도 전환 완료가 이겨 오류). 전환 완료 목록 파일은 날것 `<button>` · `<input>` · `<select>` · `<textarea>`도 오류.
- **출입구 사이 방향**: `panel` → `viewer` · `ai` → `kit`(왼쪽이 오른쪽을 가져올 수 있음). 지금은 문서 규칙과 리뷰로 지킨다.
- **기존 shadcn 파일과 kit의 관계 — 두 가지가 섞여 있다**(`references/components.md` 「변형」 열 앞 출처 표시):
  - `[재내보내기]` · `[기존]`: `kit`이 shadcn 파일(Tooltip · Dialog · Tabs · Checkbox · Label · Switch · ToggleGroup)과 이 앱의 기존 자체 부품(StatusChip · TechCorners · 빛 장식 · LoadingImage)을 **손대지 않고 그대로 다시 내보낸다**. 생김새는 원래 파일 그대로이고 시안 대조를 하지 않았다.
  - `[새로]`: `kit`의 **Button · Field는 shadcn `button.tsx` · `input.tsx`를 감싼 것이 아니라 시안 값으로 새로 만든 다른 부품**이다(Chip도 새로). 기존 `button.tsx` · `input.tsx`는 그대로 남아 기존 화면이 쓴다.
  - 그래서 **`@/shared/ui/button` → `@/shared/ui/kit`처럼 경로만 바꾸면 컴파일은 되지만 모양이 조용히 바뀐다.** shadcn 가져오기는 그 화면을 부품으로 옮길 때(시안 표식 → 대조 → 전환 완료 목록) 한꺼번에 바꾸고, 경로만 고치지 않는다. ESLint가 `@/shared/ui/button` · `@/shared/ui/input` 가져오기에 이 안내(「kit의 Button/Field는 다른 부품입니다 — 경로만 바꾸지 말고 화면을 옮길 때 교체」)를 출입구 규칙과 같은 등급으로 띄운다.
- **좌표를 재는 사진은 공용 부품으로 감싸지 않는다** → `references/layout.md` 「좌표 민감 영역」.

## 작업 순서 — 부품을 쓰거나 늘릴 때

**0. 부품표부터(훅이 막는다).** 아래 대상 파일을 쓰거나 고치기 전에 그 묶음의 부품표를 맞춘다.

| 고치는 파일 | 맞출 부품표 |
|---|---|
| `docs/mockups/scas-redesign/screens/*.js`, `assets/*.js` · `*.css` | `docs/mockups/scas-redesign/parts-plan.md` |
| `src/pages/dev/**` | `src/pages/dev/parts/parts-plan.md` |

읽는 법: 왼쪽 파일을 고치려면 오른쪽 표가 먼저 맞아야 한다. 운영 화면(`src/pages/` 나머지)에는 아직 걸지 않았다.

- 표 형식: `| 자리 | 부품 | 판정 | 메모 |`, 판정은 **그대로**(목록의 부품을 그대로 씀) · **확장**(기존 부품에 변형 추가) · **새로**(목록에 없는 부품) 중 하나. 「그대로」 부품 이름은 `components.md`의 「부품」 열에 있고 상태가 **구현됨 · 검증됨**이어야 한다. **후보 부품(목록에는 있으나 코드 없음)은 「새로」**(이미 있는 부품에 변형을 더하면 「확장」)로 적고 승인 줄을 단다.
- 확장 · 새로가 있으면 부품 설계를 사용자에게 먼저 보여 주고 `승인: MM/DD 소유자 — 부품(변형), …` 줄을 적는다. 승인 줄에 **부품 이름**을 적어야 옛 승인을 새 변경에 다시 쓰지 못한다.
- 부품과 상관없는 수정은 표 대신 `부품 불필요 — 사유` 한 줄.
- 검사: Claude는 `.claude/hooks/parts_gate.py`(쓰기 직전 훅), Codex는 훅이 없으므로 `npm run check:ui:static`이 같은 검사를 한 번 더 한다(`python3 .claude/hooks/parts_gate.py --check-all`). 관문은 **부품표가 형식에 맞는지**(판정 · 이름 · 상태 · 승인 줄)만 본다 — 고친 자리가 표에 빠짐없이 올랐는지는 보지 않으므로 그건 쓰는 사람이 맞춘다.

**1. 목록(`references/components.md`)과 다른 화면 코드에서 가까운 부품을 찾는다.** 같으면 가져다 쓰고, 승인된 차이만 변형으로 연다.

**2. 없으면 r3 시안에 먼저 그린다**(시안 = 원본). 시안에 없는 상태(예: 오류 · 잠김 · 초점)는 값을 읽을 수 없으므로 시안에 그려 사용자 승인을 받는다. 앱 코드에서 모양을 지어내지 않는다.

**3. 상태마다 계산값을 읽는다**(Playwright — 브라우저를 코드로 움직이는 도구로, 실제 마우스 올림 · 누름 · 키보드 초점을 만들어서). 실제 글꼴(IBM Plex Sans KR · JetBrains Mono)이 로딩된 뒤, 「보는 사람」 = 감정관, 움직임 줄이기 켬.

**4. 토큰 + Tailwind로 옮긴다.** 새 색 · 그림자는 `src/index.css`에 값 토큰 `--t-*` → 역할 순서로 먼저 추가(`references/tokens.md`). 조건부 클래스는 `cn()`(`@/shared/lib/utils`). 옮길 때 함정은 `references/visual-spec.md` 끝.

**5. 구현에도 같은 표식을 붙인다** — `partAttrs()`(`src/shared/ui/part-attrs.ts`)로 `data-part` · `data-part-variant` · `data-part-state` · `data-part-id`. 변형 이름은 시안 표식과 **글자까지 같게**.

**6. 자동 대조에 짝을 넣는다.** 진열 화면 픽스처(`src/pages/dev/parts/fixtures-meta.ts` 데이터 + `fixtures.tsx` 그림)에 시안과 같은 `data-part-id`로 한 줄. 부품에는 props만 넘기고 `className`을 덧씌우지 않는다(부모에서 물려받는 줄 높이 등은 픽스처의 `boxClass`로 상자에). `npx playwright test -c playwright.ui.config.ts parts-compare`가 요소 · 자식 · `::before`/`::after` **계산값**(px 0.01 이내)을 비교하고, 예외로 빼지 않은 짝은 **요소 스크린샷**(기본 차이 0픽셀)도 비교한다. 비교하는 범위 안에서 차이가 하나라도 있으면 실패.
   - 예외(`noShot` 스크린샷 생략 · `shotMaxDiffPixels` 허용 픽셀 · `compare` 대조 범위 줄임 · `ignoreSize` 크기 제외 · `ignorePlacement` 위치 제외)는 **측정한 이유**가 있을 때만 쓰고, 그 이유를 픽스처 주석과 `references/components.md` 「픽셀 대조를 뺀 자리」 · 「대조 방식이 기본과 다른 짝」에 적는다. 지금 예외가 걸린 짝과 대조하지 못한 변형은 그 절에 있다 — 「검증됨」은 「모든 변형 · 모든 픽셀이 같다」가 아니라 「적힌 범위에서 대조 통과」라는 뜻이다.

**7. 목록에 한 줄.** `components.md`에 부품 · 파일 · 원본 · 쓰는 화면 · 변형 · 상태. 상태는 **후보 → 구현됨 → 검증됨** 순서로만 올린다(구현됨 = 파일이 있음, 검증됨 = 시안 짝과 대조 통과).

### 7번째 부품 추가 체크리스트

지금 검증된 6개 다음 부품(예: 후보 Segmented)을 들일 때 빠뜨리기 쉬운 순서다. 위 작업 순서를 한 줄씩 줄인 것.

1. `references/components.md`에 그 부품 행이 있는지(없으면 후보 행부터) — 「부품」 칸은 PascalCase 이름 하나.
2. 부품표(`parts-plan.md`)에 판정 — 후보 부품은 「새로」(기존 부품에 변형 추가는 「확장」) + 사용자 승인 줄 `승인: MM/DD 소유자 — 부품(변형)`.
3. 시안 자리에 표식 4개(`data-part` · `-variant` · `-state` · `-id`) — 붙이기 전후 `mockup-snap` 차이 0.
4. 부품 파일(`src/shared/ui/<출입구>/<이름>.tsx`) + 출입구 `index.ts`에 **이름 있는 export** 한 줄(출입구 export는 모두 목록 「부품」 열에 있어야 `check:ui:static` 통과).
5. 진열 화면 픽스처 — `fixtures-meta.ts`(데이터)와 `fixtures.tsx`(그림)에 시안과 같은 `data-part-id`로 한 줄씩.
6. 대조가 안 맞는 이유가 시안 쪽 장치(주석 핀 · 겹친 틀 등)면 예외(`noShot` · `compare` · `ignore*`)를 쓰고, **측정한 값과 이유**를 픽스처 주석과 `components.md` 「픽셀 대조를 뺀 자리」 · 「대조 방식이 기본과 다른 짝」에 적는다. 모르면 예외를 쓰지 말고 묻는다.
7. `components.md` 상태를 구현됨 → (대조 통과 후) 검증됨으로, `references/visual-spec.md`에 계산값 표 한 절.
8. `npm run check:ui`(macOS가 아니면 `check:ui:static`) + `npx tsc --noEmit` · `npx vitest run` · `npm run build` · 변경 파일 `npx eslint`.

### 시안에 표식 붙이기(새 화면을 부품으로 옮기기 전 0단계)

- 부품 자리마다 표식 4개를 붙인다. 변형마다 대표 1곳에 `data-part-id`(화면-번호).
- **생김새는 바꾸지 않는다** — 붙이기 전후 `.frame`(1440px 화면 틀) 스크린샷이 같아야 한다: `npx playwright test -c playwright.ui.config.ts mockup-snap`. 기준 이미지는 표식 붙이기 **전**에만 다시 찍는다(`… mockup-snap -u`, 범위를 `mockup-snap`으로 좁혀서).
- 인라인 스타일로 복사된 반복 모양은 같은 부품 이름으로 묶는다. 값이 조금씩 다른 것(예: 칩 높이 18 · 19 · 20 · 22px)은 **변형으로 보존**이 기본 — 임의로 맞추지 않는다. 차이는 `components.md` 「같은 부품인데 값이 다른 자리」에 적고, 사용자가 통일을 원하면 그 목록으로 한 번에 정한다.
- 표식 뒤 `node scripts/ui/count-part-usage.mjs`로 「쓰는 화면」을 다시 세어 `components.md`에 적는다.

## 원칙

- **SCAS 순서 · 라벨 · 열 순서는 그대로**(시안 r1 · r2). 새 열 · 새 버튼은 **맨 끝**(시안 S08 #1 · #8).
- **AI는 「추천」** — 확정은 사람. AI가 채운 값 · 고른 후보에는 항상 AI 표시(AiTag · AiFill).
- **시안 화면은 팔레트 4종 · 기본은 SCAS 같은 흰 바탕**(2026-11-16 사용자 결정 — 시안 r1 「과학수사 다크 톤, 라이트 테마는 없다」를 바꿈). 사용자 말(원문 요지): 색이 「너무 공학도스럽고 시인성이 안 좋다」, 일반 사람이 보는 SCAS 같은 하얀 배경 · 여러 팔레트로 바꿀 수 있게. 고른 것: 팔레트 「밝게 3종 + 어둡게 1종」, 글꼴 「여러 개 받아서 선택할 수 있게」. **범위: 시안 화면(`ScasShell` · S00 진열 화면 루트의 `data-theme` 범위)만** — 기본 `scas-light`, 나머지 `light-contrast` · `light-soft` · `dark`(= r3 시안 색 그대로). `:root` 값과 기존 운영 화면(AppShell)은 다크 그대로다. 부품 픽셀 대조는 `dark`(범위 밖 = `:root`)로 돈다. 값 · 글꼴 · 화면 설정 → `references/tokens.md` 「팔레트 · 글꼴 범위」.
- **상태는 색만으로 구분하지 않는다** — 점 · 글자 · 아이콘을 같이 쓴다.
- **움직이는 효과는 AI가 실제로 일하는 자리에만.** 움직임 줄이기 설정이면 멈추고, 멈춘 모양이 최종 상태(→ `references/motion.md`).
- **스크롤 잘림 금지** — 세로 틀의 스크롤 자식은 `flex-1 min-h-0 overflow-y-auto`(→ `references/layout.md`).
- **부품은 유동형** — 부모 폭에 맞춰 늘고 줄며(`min-w-0`), 어느 폭에서 배치를 바꿀지는 화면(pages · widgets)이 정한다(→ `references/layout.md`).

## 상태 표시 — 「모름」과 「없음」, 입력 · 저장 · 오류

- **모르는 것을 없다고 보여 주지 않는다.** 검색 결과 0건과 검색 실패는 다른 모양이다. 조회 실패 = 회색 「확인 못 함 · 시:분 · 다시」, 결과 없음 = 「결과 없음(조건 …)」. 근거가 없으면 「확인 필요」(시안 S02 주황 칩).
- **실패는 그 자리에 남긴다.** 저장 실패를 잠깐 뜨는 알림으로만 처리하지 않는다 — 실패한 칸 · 줄에 표시가 남고 다시 시도 버튼이 있다.
- 입력 칸 상태(빈 칸 · 필수 · 확인 필요 · 읽기 전용 · 잠김 · 틀림 · 저장 중 · 저장 실패)와 키보드 이동은 `references/visual-spec.md` 「입력 · 저장 · 오류」에서 정한다. **틀림 · 초점은 아직 시안에 그려지지 않았다** — 쓰기 전에 시안에 먼저 그린다.
