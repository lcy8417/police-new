# 문양 가중치 — 룰베이스 설계 (2026-11-17)

> 사건 창 「문양 코드」 탭에서 넣은 문양마다 **가중치(중요도)** 를 매기는 규칙 · 점수식 · 화면 · 백엔드 계약 초안.
> 이번 시안(`police-new-scas-mock`)에서는 **화면 + 가짜 계산만** 한다. 실제 검색 순위에 쓰는 것은 운영 연결 때.

## 1. 왜

| 지금 | 문제 | 사용자 결정 |
|---|---|---|
| 검색은 **필수 문양만** 보낸다(`imageSearch` body `{ image, top, mid, bottom, outline }` — 필수 이름 배열). 필수가 아닌 문양은 검색에 안 쓰인다 | 필수는 「있다 / 없다」로 거르기만 한다. 흔한 바탕 무늬와 드문 로고 마크가 같은 무게라, 둘 다 맞은 신발과 바탕 무늬만 맞은 신발이 순위에서 갈리지 않는다 | 「우리는 가중치 기능 없는데, 룰베이스로 가중치 기능 너가 넣어야해. 이건 스펙에 써라.」(11/17) |
| 시안 r1 에 가중치가 있었으나 「근거가 없어」 뺐다(시안 S04 핀 6) | 감정관이 숫자를 손으로 매기면 사람마다 다르고 근거를 설명하기 어렵다 | → **규칙이 기본값을 정하고, 왜 그 값인지 보여 주고, 사람이 바꾸면 사람 값이 이긴다** |

## 2. 가중치 단계

| 단계 | 값 | 뜻 |
|---|---|---|
| 낮음 | 0.5 | 흔하거나 덜 믿을 만한 문양 — 맞아도 순위를 조금만 올린다 |
| 보통 | 1 | 기본 |
| 높음 | 2 | 드물어 식별력이 큰 문양 — 맞으면 순위를 크게 올린다 |

까닭:
- **세 단계만** — 감정관이 한 번 보고 고를 수 있어야 한다. 0.1 단위 슬라이더는 근거 없는 세밀함이라 r1 처럼 다시 「근거 없음」이 된다.
- **두 배씩** — 높음 하나 = 보통 둘 = 낮음 넷. 위아래가 대칭이라 설명하기 쉽다.
- **0 은 없다** — 빼려면 문양을 뺀다(가중치 0 과 「없음」이 둘 다 있으면 헷갈린다).

## 3. 기본값을 정하는 규칙

보통(단계 점수 0)에서 시작해 아래 규칙의 점수를 **모두 더한 뒤 −1 ~ +1 로 자른다**(−1 이하 = 낮음, 0 = 보통, +1 이상 = 높음). 그래서 어느 규칙도 혼자서 두 단계를 못 움직이고, 규칙끼리 부딪치면 더해서 상쇄된다.

| 순서 | 규칙 | 조건 | 점수 | 까닭 |
|---|---|---|---|---|
| R1 | 부위 | 윤곽 | −1 | 밑창 겉모양(윤곽)은 같은 틀을 쓰는 신발끼리 비슷해 식별력이 낮다. 상 · 중 · 하는 0 |
| R2 | 문양 종류(흔함) | 종류가 **선 · 무늬** | −1 | 헤링본 · 물결 같은 바탕 무늬 — 신발 DB 에 흔하다 |
| | | 종류가 **다각 · 항목** | +1 | 로고 · 글자 · 특이한 도형 — 드물다 |
| | | 삼각 · 사각 · 원 · 윤곽선 · 모름 | 0 | |
| R3 | AI 확신도 | AI 가 넣은 문양(제안 · 확인)이고 확신도 **0.5 미만** | −1 | AI 도 확신하지 못한 문양이 순위를 크게 흔들지 않게 |
| R4 | 사람 확인 | **확인 전 AI 제안** | −1 | 사람이 확인한 문양(AI · 확인, 수동)이 기준(0)이고, 확인하면 한 단계 오른다. 확인 전 제안은 원래 검색에 안 들어가므로 이 값은 「확인하면 이만큼」 미리 보기 |
| R5 | 여러 부위 반복 | 같은 이름이 **상 · 중 · 하 세 부위 모두**에 있음 | −1 | 밑창 전체를 덮는 바탕 무늬일 가능성이 크다. 두 부위까지는 0 |
| — | **사람이 고른 값** | 감정관이 카드에서 단계를 바꿈 | 규칙 무시 | **사람 값이 언제나 이긴다.** 카드에 「직접」 표시, 「규칙 기본값으로」로 되돌린다 |
| — | 필수 | 필수 켬 · 끔 | 영향 없음 | **필수는 거르기 조건, 가중치는 순위 조건** — 서로 따로 논다(아래 §4) |

읽는 법: 한 문양에 해당하는 줄을 모두 찾아 점수를 더하고 −1 ~ +1 로 자른다. 「직접」이면 계산하지 않는다.

- **종류 판정**: 문양 이름이 팔레트 어느 폴더(`src/assets/Patterns/<종류>/`)에 있는지로 정한다. 이름 앞자리(`n21_` 등)로 짐작하지 않는다 — `n73_01` 은 다각, `n73_02` 는 원처럼 앞자리가 같아도 종류가 다르다.
- **비교는 이름 기준**(docs/pattern-data-model.md §2) — 경로가 달라도 이름이 같으면 같은 문양.
- **화면에 까닭을 보인다**: 카드 단계 옆 마우스 설명에 「R2 선 −1 · R5 상·중·하 반복 −1 → 낮음」처럼 걸린 규칙을 적는다.

### 예 — 시안 값(감정물 00001-25-0649_2)

| 부위 · 문양 | 상태 | R1 | R2 | R3 | R4 | R5 | 합 → 단계 |
|---|---|---|---|---|---|---|---|
| 상 n32_04 | AI · 확인 0.93 | 0 | 선 −1 | 0 | 0 | 상·중·하 −1 | −2 → **낮음 0.5** |
| 상 n21_05 | AI 제안 0.61 | 0 | 무늬 −1 | 0 | −1 | 0 | −2 → 낮음 0.5(확인하면 −1 → 낮음 그대로) |
| 중 s81b | AI 제안? 0.42 | 0 | 항목 +1 | −1 | −1 | 0 | −1 → 낮음 0.5(확인하면 0 → **보통 1**) |
| 윤곽 s10c | 수동 | −1 | 윤곽선 0 | 0 | 0 | 0 | −1 → **낮음 0.5** |

## 4. 점수식

```
Q = 검색에 쓰는 문양 = 4부위의 (부위, 이름) 가운데 「확인 전 AI 제안」을 뺀 것
R = Q 가운데 필수
w(부위, 이름) = 위 §3 의 값(사람 값이 있으면 사람 값)

후보 신발 S 가
  R 의 문양 하나라도 같은 부위에 없으면 → 제외(지금 필수 거르기 그대로)
  아니면 문양 점수 = Σ{ w | Q 의 문양이 S 의 같은 부위에 있음 } ÷ Σ{ w | Q 전체 }   (0 ~ 1)
Q 가 비면 문양 점수 없음(이미지 유사도만)
```

- **같은 부위끼리만** 맞춘다(상의 n32_04 는 신발의 상 n32_04 와만 맞음).
- **이미지 유사도와 섞는 비율**(예 `최종 = α × 이미지 + (1 − α) × 문양`)은 **운영 연결 때 결정** — 백엔드 이미지 검색 점수의 분포를 보고 정한다. 이번 시안은 문양 점수만으로 가짜 순위를 낸다.

### 예시 계산

Q = 상 n32_04(0.5, 필수) · 중 n32_04(0.5, 필수) · 하 n32_04(0.5) · 중 s81b(2 — 감정관이 높음으로 바꿈) · 윤곽 s10c(0.5). 분모 = 0.5 + 0.5 + 0.5 + 2 + 0.5 = **4.0**.

| 후보 | 가진 문양(같은 부위) | 필수 | 분자 | 문양 점수 | (가중치 없이 — 모두 1) |
|---|---|---|---|---|---|
| A | 상 n32_04 · 중 n32_04 · 하 n32_04 · 중 s81b | 통과 | 0.5 + 0.5 + 0.5 + 2 = 3.5 | **0.88** | 4 ÷ 5 = 0.80 |
| B | 상 n32_04 · 중 n32_04 · 하 n32_04 · 윤곽 s10c | 통과 | 0.5 × 4 = 2.0 | **0.50** | 4 ÷ 5 = 0.80 |
| C | 상 n32_04 · 하 n32_04 · 중 s81b | **중 n32_04 없음** | — | **제외** | 제외 |

가중치가 없으면 A · B 가 0.80 으로 같지만, 드문 항목 마크(s81b)가 맞은 A 가 앞선다.

## 5. 화면 (이번 시안)

| 자리 | 모양 · 동작 |
|---|---|
| 4부위 문양 카드 | 그림 · 이름 · (AI 면 확신도) · 필수 토글 · **가중치 세 칸(낮 · 보 · 높)** · 빼기. 고른 칸이 지금 단계. 규칙 값이면 「규칙」, 사람이 바꾸면 「직접」(brand) 표시. 마우스 설명 = 걸린 규칙(§3 「화면에 까닭을 보인다」). 확인 전 AI 제안은 흐리게(검색에 안 들어감) |
| 검색 조건 탭 | 가중치 규칙 요약(R1 ~ R5 한 줄씩) · 「직접」 개수 · **「규칙 기본값으로」**(사람 값을 모두 지움) |
| 검색 이력 탭 | 검색 한 번 = 한 줄. 그때의 부위별 문양에 **필수 · 가중치(단계 · 규칙/직접)** 를 같이 남겨, 「이 조건 다시 불러오기」로 문양 · 필수 · 가중치 · 매칭 조건을 그대로 되살린다 |
| 「검색」 | 가짜 신발 DB(진열용)에 §4 식을 그대로 돌려 결과 수 · 상위 3 을 이력 줄에 남긴다 |

## 6. 데이터 표현 — 기존 튜플을 깨지 않는다

- 사건 문양은 지금처럼 `[이름(또는 경로), 필수]` 2요소 튜플(docs/pattern-data-model.md §2). **가중치를 튜플 셋째 칸에 넣지 않는다** — `item.length == 2` 로 crime/shoe 를 가르는 레거시 판별(`onlyPatternName`)이 깨진다.
- 사람이 고른 값만 따로 든다: `weightOverrides: { [부위]: { [이름]: "low" | "normal" | "high" } }`(이름 기준, 문양 카드 덧붙임 `patternMeta` 와 같은 모양). 규칙 값은 저장하지 않고 그때그때 계산한다(규칙이 바뀌면 다시 계산).
- 순수 함수: `src/widgets/pattern-code/model/weight-rules.ts`(규칙 · 단계) · `match-score.ts`(점수식) + 같은 폴더 단위 테스트.

## 7. 백엔드 계약 초안 (운영 연결 때)

`POST /crime/:aprthngNo/search?page&similarity` body — **지금 필드는 그대로, `weights` 만 선택 필드로 더한다**(docs/api-communication.md §2(B)).

```jsonc
{
  "image": "<base64>",
  "top": ["n32_04"], "mid": ["n32_04"], "bottom": [], "outline": [],   // 지금 그대로 = 필수(거르기)
  "weights": {                                                          // 새 선택 필드 — 없으면 지금 동작
    "top":     { "n32_04": 0.5 },
    "mid":     { "n32_04": 0.5, "s81b": 2 },
    "bottom":  { "n32_04": 0.5 },
    "outline": { "s10c": 0.5 }
  }
}
```

- `weights` 의 키 = 검색에 쓰는 **모든** 문양(필수 아닌 것 포함), 값 = 0.5 · 1 · 2. 필수 배열(`top` … `outline`)은 지금처럼 거르기에만 쓴다.
- 이미지 POST 규약 그대로(무변환 · `data:` 접두어 제거). 이름만 보낸다(`stripPatternPath`).
- 응답 `result[]` 에 선택 필드 `pattern_score`(0 ~ 1)를 더하면 화면이 이미지 유사도와 따로 보일 수 있다.
- 검색 이력 저장(`app.search_snapshot.ptrn_snapshot`)에 `weights` 와 「직접」 여부도 남긴다(이력에서 다시 불러오기).

## 8. 열린 질문 (감정관 확인 필요)

1. **R5(세 부위 반복 −1)** — 밑창 전체 바탕 무늬를 낮추는 것이 맞나? 필수로 건 주 문양(예 헤링본)이 「낮음」으로 보이는 것이 어색하지 않나?
2. **R2 흔함 분류** — 선 · 무늬 = 흔함, 다각 · 항목 = 드묾이 실제 DB 빈도와 맞나? 운영 때는 신발 DB 의 문양별 빈도(드물수록 높음)로 바꿀 수 있다.
3. **상 · 하 가산** — 앞축(상) · 뒤축(하)이 중(아치)보다 잘 찍혀 식별력이 높다면 R1 에 상 · 하 +1 을 둘까?
4. **SCAS 「개수」(0–9 · 10이상)** — 가중치에 쓸까(예 개수가 많을수록 바탕 무늬)? SCAS 에서 필수를 걸면 개수가 0 으로 바뀌던 동작의 뜻도 아직 확인 필요(시안 S04 핀 6).
5. **이미지 유사도와 섞는 비율 α** — 운영 연결 때 결과 분포를 보고 정한다.
6. **확인 전 AI 제안** — 지금처럼 검색에서 빼는 것이 맞나, 낮은 가중치로 넣을까?
7. **윤곽 −1** — 윤곽을 직접 넣는 경우가 드물다면(시안: 윤곽은 AI 미지원), 넣었다는 것 자체가 의미 있는 단서일 수 있다.
