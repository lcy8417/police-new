## 1. 왜 하나

- r3 시안(16화면)이 승인됐고 부품 체계(출입구 4개 · 부품 6개 검증)도 섰다. 이제 **지금 기능부터** 시안 모양으로 옮긴다.
- 실제 데이터 연결까지 한 번에 하면 화면 생김새 결정과 배선 결함이 뒤섞인다. 그래서 **생김새를 가짜 데이터로 먼저 확정**하고, 연결은 다음 단계에서 같은 컴포넌트에 값만 꽂는다(romang 「창은 하나, 입구는 둘」 · 「복사본 없이 원본 하나」).
- 시안 단계에서 나오는 결과물(표시 컴포넌트)이 그대로 운영 화면이 되므로, 나중에 다시 짜지 않는다.

## 2. 목표 · 비목표 · 반목표

**목표**
1. 화면 11개가 `/dev/s00` … `/dev/s14`에서 **로그인 · 백엔드 없이** 열리고, 화면끼리 시안 흐름대로 이동한다(목록 → 상세 → 편집 → 문양 → 결과 → 대조 → 확인).
2. **지금 기능 전부**(§5-1 점검표)가 11개 화면 어딘가에 자리를 갖는다. 빠진 기능 0건.
3. 화면은 `src/widgets/<화면>/ui/`에 **값(props)만 받아 그리는 표시 컴포넌트**로 만든다. 서버 호출 · 전역 상태 0줄.
4. 화면마다 **정상 · 불러오는 중 · 조회 실패 · 결과 없음(해당 화면만)** 과 **권한 차이**(지금 기능 권한 코드 기준)를 가짜 데이터로 전환해 볼 수 있다.
5. 화면에 필요한 공용 부품을 `police-ui-design` 절차대로 채운다(§8). 생김새는 r3 계산값과 대조 통과.

**비목표(이번에 안 함)**
- 실제 API 연결, 지금 페이지 교체, 사이드바(AppShell)를 시안 껍데기(ScasShell)로 바꾸기.
- 화면 S08 검증·결재 · S09 감정서 · S11 수집 검수 · S12 기초코드 · S15 모델 관리.
- r3의 **+α 신규**(사업계획서 기능)와 **실증 신규 업무**(교차 검증 · 결재 · 감정서 · 확인대상 · 의뢰 진행 단계 · 역할별 첫 화면 · 할 일 타일).
- 백엔드 수정.
- 시안 화면의 배포 · 외부 공유(`/dev/*`는 개발 실행에서만 열림).
- 좌표 캔버스 자리(자르기 · 회전 · 경계선 · 다각형 · 4점)의 실제 조작 — 이번엔 겉모습만.

**반목표(이렇게 되면 기술적으로 돌아가도 실패)**
- 지금 페이지 · 기능 파일이 바뀌어 지금 앱 동작이 달라짐.
- 실제로 없는 AI 기능이 작동하는 것처럼 보이는 화면(예: 대응점 39개 · AI 리랭킹 · AI 1차 점검).
- 시안에 없는 모양을 지어냄(정본 스킬 「하지 말 것」).
- 표시 컴포넌트 안에 가짜 데이터나 서버 호출이 섞여, 나중에 운영 연결 때 다시 짜야 함.
- 실제 사건 사진 · 실명 사용.

## 4. 접근 방식 (검토한 것)

**시안을 어디에 만드나**
- **A. 별도 진열 주소 + `widgets/` 표시 컴포넌트(채택)** — 지금 앱 무변경, 나중에 운영 페이지가 같은 컴포넌트를 가져다 씀.
- B. 지금 페이지 자리를 바로 교체하고 API만 가짜로 — 시안 작업 동안 지금 앱이 멈춤. 「나머지 건드리지 말 것」과 충돌해 버림.
- C. 부품만 `/dev/parts`에 채우고 화면은 나중 — 화면 흐름을 눌러 볼 수 없어 시안 검토가 안 됨.

**커맨드센터를 쪼개나**
- **시안대로 나눔(채택)** — 시안의 화면 단위 · SCAS 버튼 줄 · 흐름을 그대로 씀. 「한 화면에서 다」 장점은 잃음.
- 4열 유지 + 모양만 — 작지만 시안 흐름과 어긋남.

**무엇까지 담나**
- **① 지금 기능만(채택)** — 운영 연결 때 빈 버튼이 없다.
- ② 시안 전부 — 없는 AI 기능이 있는 척, 연결 때 대부분 숨겨야 함.
- ③ 배치만 + 「준비 중」 — 빈 칸이 많음.

**어떻게 진행하나**
- **병렬 트랙(채택, 사용자)** — 부품은 출입구별, 화면은 도메인별로 동시에. 토큰 비용이 크고 공유 파일 충돌 위험 → §9 단일 담당으로 막음.
- 순서대로 1명 — 싸지만 느림.

### 5-2. 담을지 판정 규칙

시안 요소 하나하나를 아래 순서로 판정한다. 처음 맞는 줄이 답이다.

1. §5-1의 지금 기능이 쓰는 자리 → **담는다.**
2. r3 대조표 구분이 **+α 신규**이거나, 실증 신규 업무(교차 검증 · 결재 · 감정서 · 확인대상 · 의뢰 진행 단계 띠 · 역할별 첫 화면 · 할 일 타일 · AI 제안/점검 카드) → **뺀다.**
3. 「SCAS 유지」 배치 · 라벨 · 버튼 순서 · 열 순서 → **담는다**(SCAS 표에 값이 있으면 가짜 값으로 채움, 동작이 없는 버튼은 화면에 두되 비활성 + 「준비 중」 툴팁). 근거: 정본 스킬 원칙 「SCAS 순서 · 라벨 · 열 순서는 그대로」.
4. 「개선」 · 「인터뷰」 중 지금 데이터(지금 API 타입 · SCAS 표)로 그릴 수 있는 것 → **담는다**. 그릴 데이터가 없으면 → **뺀다.**
5. 애매하면 멈추지 않고 뺀 쪽으로 진행하고, 화면 노트(§9-4)에 한 줄 남긴다. 마감 때 사용자에게 한 번에 보여 준다.

## 6. 구조

### 6-1. 배치 (FSD, 지금 규칙 그대로)

```text
src/
├── shared/ui/{kit,viewer,ai,panel}/   # 공용 부품(트랙 1이 채움)
├── widgets/<화면>/
│   ├── index.ts                       # 배럴 — 진열 페이지 · 나중 운영 페이지가 함께 가져옴
│   ├── model/types.ts                 # 화면이 받는 값 타입(props)
│   └── ui/<화면>Screen.tsx             # ⭐ 표시 정본 1벌(서버 호출 · 전역 상태 0줄)
└── pages/dev/
    ├── parts/parts-plan.md            # 부품표 관문이 읽는 단 하나의 부품표(공유 — §9 단일 담당)
    ├── index/                          # (새로) `/dev` 목차 — 11개 화면 · 케이스 바로가기
    └── s01/ …                          # 화면별 진열 페이지
        ├── mock-cases.ts              # 케이스별 가짜 값(정상 · 불러오는 중 · 실패 · 결과 없음 · 권한)
        └── S01DevPage.tsx             # 정본 위젯을 가져와 가짜 값 · 이동 콜백만 넘김
```

- **값 타입**: 지금 엔티티 타입이 있으면 그대로 쓴다(`Crime` · `Shoe` · `AdminUser` · `AdminSession` · `AdminEvent` · `MatchCorrespondence` · `Alignment` · `PatternEntry` …). 타입이 없는 레거시 API(`services/api.js`의 `patternsExtract` · `imageSearch` · `fetchSimilarity` 응답)는 위젯 `model/types.ts`에 **지금 응답 모양 그대로** 최소 타입을 정의하고, 출처 함수 이름을 주석으로 단다.
- **상태 값**: 화면은 `status: "loading" | "error" | "empty" | "ready"`(화면에 따라 일부)를 받는다. 실패를 `0` · 빈 배열로 덮지 않는다(정본 스킬 「모르는 것을 없다고 보여 주지 않는다」).
- **콜백**: 버튼마다 `on…` 콜백을 받는다. 진열 페이지에서는 다음 화면으로 이동하거나 알림(toast)만 띄운다. 빈 함수로 방치 금지.
- **좌표를 다루는 캔버스**(문양 경계 `PatternCanvas`, 크롭 · 회전 `Canvas.jsx`, 다각형 `PolygonCaptureCanvas`, 정렬 `AlignmentCaptureCanvas`, 각도보정 4점): 좌표 수학 변경 금지(`CLAUDE.md` 치명 규칙). 위젯은 이 자리를 **끼워 넣을 칸(`ReactNode` 슬롯)** 으로 받는다. 운영 연결 때 기존 캔버스를 그대로 끼운다. **이번 시안 단계에서는 이 자리를 조작할 수 없어도 된다(겉모습만).** 진열 페이지는 칸에 가짜 사진 + 시안 도구 모양(자르기 틀 · 회전 손잡이 · 확대경 · 십자선 · 축소판 지도 · 경계선 · 다각형 · 4점)을 **고정 위치 장식(`pointer-events-none`)** 으로 넣는다. 이 장식은 S03 · S04 · S06 화면 폴더 안의 표시 조각이고 공용 부품이 아니다(`references/layout.md` 「좌표 민감 영역」). 운영 연결 때 이 모양을 기존 캔버스 쪽에 입힐지는 그 단계에서 정한다. *(설계자 판단)*
- **PointPairs(F26)** 는 `MatchBox` 값을 받아 번호 박스 · 강조를 **그리기만** 하는 viewer 부품이다(지금 `CorrespondenceMap` · `MatchViewer`가 하는 표시와 같은 범위). 박스 선택 · 호버 강조는 콜백으로 밖에 알린다.
- **상태는 어디에 두나** *(설계자 판단)*: 저장되거나 서버로 가는 값 — 입력 칸 값, 배치된 문양 · 필수 표시, 고른 검색 이미지, 편집 단계 값, 판정, 권한 스위치, 필터 — 은 **모두 props + `on…` 콜백(제어형)**. 진열 페이지가 이 값을 `useState`로 들고 있어 눌러 보면 바뀐다. 저장되지 않는 화면 내부 모양 — 펼침/접힘, 호버, 탭 선택, 보기 방식(원본 · 이진화 등) 중 저장 안 하는 것 — 만 위젯 안 상태로 둔다. 헷갈리면 제어형으로 둔다.
- **권한 차이** *(설계자 판단)*: 화면은 `features: FeatureCode[]`(+ 관리자 여부)를 받아 버튼을 숨기거나 잠근다. 잠그는 기준은 **지금 앱이 쓰는 코드 그대로**(사건 등록 `CRIME_REGISTER` · 조회 · 판정 저장 `CRIME_SEARCH` · 신발 보기 `SHOE_VIEW` · 신발 등록·수정 `SHOE_EDIT` · 관리자). 실증 업무 코드 8종(`EXAM_DECIDE` 등)으로 새로 잠그지 않는다. 단 S13 권한 스위치는 **지금 화면처럼 서버가 주는 기능 목록 12종을 그대로** 보여 준다(지금 기능 F31이므로).
- **껍데기**: 진열 페이지는 시안 껍데기 `ScasShell`(panel)로 감싼다. 운영 앱의 `AppShell`은 그대로 둔다(부품 목록 「전환은 검증 후 한 번에」).

### 6-2. 진열 주소 규약

- `/dev`, `/dev/s00` … `/dev/s14`는 `/dev/parts`처럼 **개발 실행에서만** 열리고 로그인 가드 밖에 둔다(`src/App.jsx`에 라우트만 추가, 기존 라우트 무변경).
- 케이스 전환 `?case=ready|loading|error|empty`, 권한 전환 `?as=admin|investigator|readonly`(이름은 진열용, 실제 역할 코드와 무관). 화면 위에 작은 전환 막대를 둔다(시안 「보는 사람」과 같은 자리). 권한 묶음: `admin` = 관리자(전부), `investigator` = `CRIME_REGISTER` · `CRIME_SEARCH` · `SHOE_VIEW`, `readonly` = `SHOE_VIEW`만. *(설계자 판단)*
- 화면 간 이동은 진열 주소끼리 연결한다(S01 행 → `/dev/s02?id=…`).

### 6-3. 가짜 데이터 규칙

- 사람 · 사건 정보는 모두 가짜, 이름은 가림(`박○○`). 사건 번호 · 숫자는 시안 예시값과 맞춘다(예: 감정번호 00001-25-0646).
- 현장 사진은 실제 사건 사진 금지. 시안의 `M.photo` · `M.sole` 그림을 정적 이미지(또는 SVG 컴포넌트)로 옮겨 쓴다. 신발 사진은 `src/assets/Shoes`의 기존 이미지를 써도 된다.
- 문양 아이콘은 `src/assets/Patterns`(지금 경로 · 이름 규약 `docs/pattern-data-model.md` 그대로).

- 시안에 없는 상태 모양(틀림 · 초점 테두리 등)이 필요하면 **시안에 먼저 그린다**(정본 작업 순서 2). 이 경우 그 화면 트랙은 시안 파일을 고칠 수 있다(부품표 관문 대상 — `docs/mockups/scas-redesign/parts-plan.md` 먼저).

여러 갈래가 동시에 고치면 깨지는 파일은 **오케스트레이터만** 고친다. 갈래는 자기 노트(§9-4)에 「무엇을 어떻게 바꿔 달라」를 적고, 오케스트레이터가 차례 1.5 · 3에서 합친다.

- `src/App.jsx`(라우트 — 트랙 0에서 11개 자리를 미리 만들어 둠)
- `.claude/skills/police-ui-design/references/*.md`(components · visual-spec · tokens · motion · layout)
- `src/pages/dev/parts/parts-plan.md`, `docs/mockups/scas-redesign/parts-plan.md`
- `src/pages/dev/parts/fixtures*.ts(x)`(부품 진열) — 갈래마다 자기 출입구 이름의 별도 진열 파일을 만들고 오케스트레이터가 연결하는 방식도 허용
- `src/index.css`(토큰), `scripts/ui/ui-converted.txt`
- 출입구 배럴 `src/shared/ui/<출입구>/index.ts`는 **그 출입구 갈래만** 고친다(트랙 1). 트랙 2는 배럴을 고치지 않는다.

### 9-3. 갈래가 지킬 경계

- 지금 페이지 · 기능 · 위젯 파일(§10의 「무변경 목록」)을 고치지 않는다.

- 공용 부품이 모자라면 화면 안에 임시로 만들지 말고 멈춰서 노트에 적는다(차례 1.5 이후 추가는 사용자 확인).

## 13. 변경 r2 — 「전부 시안 그대로」 (2026-11-16)

**사용자 결정(원문 선택 「전부 시안 그대로」)**: 1차 결과(①안 — 지금 기능만)를 보고 「로그인부터 우리가 보여준 그 시안과 다른데?? 애니메이션 아에 없네」. 담을 내용을 **②안 — 시안 전부**로 바꾼다. 이 절이 §3 「담을 내용」 · §5-2 · §5-3 「빼는 것」 · §8 「빼는 부품」보다 앞선다.

1. **담는 범위**: 11개 화면은 r3 시안 `screens/sNN-*.js`의 `ours()`에 그려진 것을 **전부** 그린다 — +α 신규(AI 시연 애니메이션 · AI 타일 · 히트맵 · 대응점 · 깔때기 · 단계 띠 · AI 점검/제안 카드 · 역할별 할 일 등)와 실증 업무(교차 검증 · 결재 요청 · 확인대상 등) 포함. 시안의 SCAS 열 순서 · 라벨이 지금 기능 표와 다르면 **시안을 따른다**(예: S04 검색 이력 열).
2. **지금 기능은 그대로 유지**: 1차에서 넣은 지금 기능(§5-1 F1~F33)과 그 동작 · 테스트는 지우지 않는다. 시안에 없던 지금 기능(길이측정 · 노이즈제거 · 정렬 설정 등)은 1차에서 덧붙인 자리 그대로 둔다.
3. **신규 표시와 끄기**: +α · 실증 업무 요소는 위젯 안에서 `showPlus`(기본 true) prop 하나로 한꺼번에 숨길 수 있게 감싸고, 루트에 `data-plus` 속성을 단다. 진열 막대에 「신규 기능 보기」 켜기/끄기(`?plus=0`)를 둔다. 운영 연결 때는 `showPlus={false}`로 시작한다.
4. **동작 없는 신규 버튼**: 시안처럼 활성 모양으로 그리고, 진열 페이지 콜백은 「시안 — 기능 준비 중」 알림만 띄운다(§5-2 규칙 3의 비활성 처리는 지금 기능 영역의 SCAS 버튼에만 계속 적용).
5. **보는 사람 = 시안 역할**: 진열 막대의 보는 사람을 시안 `M.ROLES`와 같게 바꾼다 — 수사관(investigator) · 감정관(analyst) · 기술책임자(verifier) · 관리자(admin) + 보기 전용(readonly, 진열용). 시안 요소의 `data-role`대로 보인다. 지금 기능 권한 코드는 실증 설계서 `police-server/docs/superpowers/specs/2026-11-12-pilot-platform-schema-design.md` 기능 표(§ 권한, 165~172줄 부근)의 역할 배정으로 각 역할에 매긴다. 각 화면 기본 보는 사람은 시안 화면의 기본 역할.
6. **애니메이션**: 시안에 있는 움직임(S00 시연 14초 반복 · 스캔 선 · 진행 막대 반짝임 · 실시간 점 · 새 행 빛)은 시안대로 넣는다. 움직임 줄이기 설정이면 다 끝난 모양으로 멈춘다(`references/motion.md`). §7 「AI가 실제로 일하는 자리에만」 규칙은 r2에서 「시안이 움직이는 자리에만」으로 읽는다.
7. **새로 만들 공용 부품(이 결정으로 승인)**: §8에서 뺐던 StatTile · CheckList · AiSuggestion(ai) · HeatOverlay(viewer) · Stepper(panel)와, 시안 대조 중 필요해지는 같은 성격의 부품. 절차는 §8과 같다(시안 계산값 → 토큰 → 진열 → 대조).
8. **색 외 표식 · 슬라이더**: 시안에 없는 모양은 여전히 지어내지 않는다(정본 「하지 말 것」). S03 보정 칸은 시안 모양을 따른다.

## 14. 변경 r3 — 시인성 · 편의 피드백 (2026-11-16)

**사용자 전달 피드백(원문 요지)**: ① 색이 「너무 공학도스럽고 시인성이 안 좋다」 — 일반 사람이 보는 SCAS 같은 **하얀 배경**, 여러 팔레트로 바꿀 수 있게. ② 글꼴을 D2Coding 등으로 바꿔 잘 보이게. ③ 검색 결과 **자동 모드** — 누르면 결과 페이지가 넘어가거나 스크롤이 내려감, 주기는 1초 · 2초 등 감정관이 미세하게 고름, 수동/자동 모드. ④ 보이는 항목 중 일부만 보는 **필터 · 검색**. ⑤ 족적 **1개 · 3개 · 5개 보기** 등 편의 기능 최대한.
**사용자 결정**: 팔레트 = 「밝게 3종 + 어둡게 1종」, 글꼴 = 「여러 개 받아서 선택할 수 있게」.

이 절이 정본 원칙 「과학수사 다크 톤. 라이트 테마는 없다」(시안 r1)를 **바꾼다** — `police-ui-design` 스킬 원칙 · tokens.md를 함께 고친다.

1. **팔레트 4종(시안 화면 범위)**: `scas-light`(기본 — SCAS처럼 흰 바탕 · 진한 글자 · 파란 강조), `light-contrast`(흰 바탕 · 글자/선 더 진하게 · 굵은 초점 — 저시력 · 장시간 대조용), `light-soft`(옅은 회색 바탕 · 눈부심 적게), `dark`(지금 r3 시안 색 그대로). 값은 `--t-*` 토큰을 `[data-theme="…"]` 범위에서 다시 정의해 만든다. **`:root` 기존 값은 바꾸지 않는다** → 기존 운영 앱 화면은 그대로(반목표 유지). 시안 화면은 `ScasShell`(+ S00 bare 화면) 루트가 `data-theme`을 단다.
2. **상태색 대비**: 밝은 팔레트마다 본문 글자 대비 WCAG AA(4.5:1) 이상, 상태색(ok · warn · danger · ai · brand) 칩 글자도 AA. AI 청록 · 경고 주황 등 의미 색은 팔레트가 바뀌어도 같은 뜻.
3. **글꼴 선택**: 내려받아 저장소에 넣는(인터넷 없어도 되는 내부망 기준) 글꼴 여러 개 — **D2Coding(기본)** · Pretendard · 나눔고딕 · 나눔바른고딕 · IBM Plex Sans KR(지금) · Noto Sans KR. 모두 공개 라이선스(OFL 등)만. `--font-ui` · `--font-code`를 범위 변수로 바꿔(`:root` 기본값은 지금 그대로) `[data-font="…"]`로 고른다. 숫자 · 번호는 고른 글꼴에 관계없이 고정폭이 필요한 자리만 `--font-code`.
4. **화면 설정 창(사용자용, 진열 막대 아님)**: ScasShell 상단 오른쪽에 「화면 설정」 — 팔레트 4 · 글꼴 · **글자 크기**(보통 · 크게 · 아주 크게, 루트 글자 배율) · 움직임 줄이기. 고른 값은 이 브라우저에 기억(localStorage, 실패해도 기본값으로 동작).
5. **자동 모드(S05 검색 결과 — 주 대상)**: 「수동 · 자동」 전환. 자동이면 정한 주기마다 다음 후보로 초점 이동 → 화면 끝이면 스크롤 → 쪽 끝이면 다음 쪽. 주기는 **0.5초 단위로 0.5~10초**(빠른 고르기 1 · 2 · 3 · 5초 + 미세 조정). 진행 표시(남은 시간 막대 · n/전체), 일시정지/재개(Space), 앞뒤 한 칸(← →), 마우스를 카드에 올리거나 확인대상 ★를 누르면 잠시 멈춤, 마지막 후보에서 멈춤. 「어디까지 봤는지」(시안 핀 4) 표시와 연결. 같은 자동 넘기기를 S06 후보 넘기기 · S10 카드 보기에도 쓸 수 있게 공용 부품으로 만든다.
6. **필터 · 검색(목록이 있는 모든 화면)**: S01 · S05 · S07 · S10 · S13 · S14에 「빠른 찾기」 글자 검색(지금 보이는 목록 안에서 바로 거름) + 화면별 필터 칩(예: S05 유사도 등급 · 본 것/안 본 것 · 확인대상, S01 진행 상태 · 사건결과) + **보이는 열/항목 고르기**(표는 열 켜기/끄기, 카드는 표시 항목 켜기/끄기 — SCAS 열 순서는 유지). 고른 값은 화면별로 기억.
7. **보기 개수 · 편의**: S05 결과 「1 · 2 · 3 · 4 · 5 · 6개씩」(시안 1–4열 + 확장), S06 비교 「1:1 · 1:3 · 1:5」(현장 1장 대 후보 n장 나란히), S07 이미지 블록 「1 · 3 · 5개씩」, S10 카드 「작게 · 보통 · 크게」. 공통: 썸네일 크기 조절, 전체 화면 보기, 키보드 단축키 안내(? 키), 이전/다음 이동.
8. **부품**: 새 공용 부품 — `FilterBar`(kit: 검색 + 필터 칩 + 지우기), `ColumnPicker`(kit), `ViewCountSwitch`(kit, Segmented 기반), `AutoPlayControl`(ai 또는 kit: 수동/자동 · 주기 · 진행 · 일시정지), `ThemeSettings`(panel: 화면 설정 창). 그리고 테마 · 글꼴 범위 토큰. 이 결정으로 승인.
9. **대조**: 부품 픽셀 대조는 시안이 어두우므로 `dark` 팔레트로 돌린다. 밝은 팔레트는 대조 대상이 없으므로 대비 검사(자동 · AA)와 캡처 확인으로 갈음.
