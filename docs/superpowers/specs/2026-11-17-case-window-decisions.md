# 사건 창 · 작업판 시안 결정 기록 (2026-11-16 ~ 11-17)

> 사용자와 화면을 하나씩 보며 정한 것을 한곳에 모은 기록이다. 시안(`police-new-scas-mock`)의 정본 설계서(`2026-11-16-scas-screens-mock-design.md`)를 **이 문서가 덮어쓴다**(뒤에 정한 것이 먼저). 가중치 규칙은 `2026-11-17-pattern-weight-rule-design.md`, 디자인 규칙은 `.claude/skills/police-ui-design/SKILL.md`(r4: 목록 · 앱 틀 · 창 생김새는 로망 정본, 색은 경찰 토큰), DB 는 `police-server/docs/superpowers/specs/2026-11-12-pilot-platform-schema-design.md`.
> 따옴표 안은 사용자 원문(맞춤법 그대로).

## 1. 앱 틀
| 결정 | 근거(사용자) |
|---|---|
| 왼쪽 사이드바 없음. 남색 위 막대 한 줄(로고 · 화면 이름과 건수 · 바로 찾기 · 신발 DB · 관리 ▾(관리자) · 화면 설정 · 사용자) | 「신발 디비도 상단에 조그만한 버튼으로 해서 슬라이드 패널 … 왼쪽에 사이드 바가 필요업서」 → 제안 「응」 |
| 신발 DB = 위 막대 단추 → 오른쪽 큰 슬라이드 패널(사건 창과 같은 틀). 사용자 관리 · 사용 기록 = 관리 ▾ → 전체 화면 | 같음 |
| 검색 칸은 하나(위 막대 바로 찾기가 목록을 거름) | 「위 검색도 2개고 … 컴팩트하게」 |

## 2. 사건관리 목록
| 결정 | 근거 |
|---|---|
| 로망 목록 표 부품, 머리 · 칸 같은 열 격자(정렬 맞춤) | 「테이블 컴포넌트 로망꺼 가져오면 안되나?? 지금 너무 못생김」 「칸 정렬도 안맞네」 |
| 열: 이미지(크게, 행 64) · 감정번호/사건명 · 의뢰관서 · 개수 · 등록일자 · 결과(발견·불발·불능 한 칸) · 진행 · 사건 진행(단계 알약 + 그 단계 단추 하나) | 「중요한 거 제외하고 나머지는 안보이는게」 「이미지가 좀 잘 보여야」 「검색 확인 검증 버튼이랑 사건진행 겹치잖아」 「발견 불발 불능도 좀 컴팩트하게」 |
| 목록보기/문양보기 · 상세 검색 · 엑셀 · 열 선택 · 열 보기 전환 없음. 거르기 = 칩(빠른 보기 · 진행 · 내 담당만) | 「목록보기 문양보기 빼고, 상세 검색은 그냥 필터로 … 엑셀 이런 거 다 버리고」 |
| 목록에 AI 표식 · 펼침 요약 · 공문 자동 줄 없음 | 「아래도 AI 이런 거 다 빼. 여기는 리스트만 … 전문적으로」 |

## 3. 사건 창(사건 행을 누르면 오른쪽에서 큰 창)
| 결정 | 근거 |
|---|---|
| 로망 거래처 창 이식: 위 작업 탭 줄(열린 사건들, 최대 8, 오른쪽 「+」= 사건 찾아 열기 · 기능 열기) · 남색 머리 · 왼쪽 이미지 목록(기본 접힘 64px 썸네일 줄) · 오른쪽 작업 탭 | 「슬라이드 패널 크게 뜨는 거 … 사건 클릭하면 사건 상세」→「응 해」, 「왼쪽 사이드바 기본적으로 접혀있을까??」, 「오른쪽에 + 버튼으로 기존 기능들이나 사건들 추가」 |
| 흐름 = 머리 안 한 줄(접수 › 1차 작업 › 검색·판정 › 교차 검증 › 감정서), 알려 주기만. **결재 없음** | 「이단계에서 할 일은 없애고 … 플로우가 이렇다 이정도만. 결재는 없어」 |
| 작업 탭: 사건 정보 · 이미지 편집 · 문양 코드 · 검색 결과 · 정밀 대조 + 사건 단위 결과 확인. 탭 이름 뒤 ✓ · 빈 칸 수 · ! 표시 | 「탭이 더 잘 보이고」 |
| 공통 결: 먹색 작업판(`data-theme="dark"`) · 밝은 머리/보조 칸 · 칸 사이 가는 선 · `WorkbenchButton`(글자 · 옅은 판 · 채움) · 아이콘 타일 · 밑줄 탭 모양 소제목(PaneHead) · 설명 문장/점선 상자/색 띠 최소 | 「컴팩트하면서 고급지게」 「좌 중앙 우 느낌이 다르면 구분선이나 차이 … 알록달록은 싫고」 「옆에 클릭 선 말고 … 전문적 느낌 … 아카데믹한」 「취소 확인 저장 이런 버튼이 너무 아카대믹함」 |

### 3-1. 사건 정보
| 결정 | 근거 |
|---|---|
| 사건정보 · 현장 이미지 정보는 밑줄 탭으로 좌우, 높이 꽉 · 왼쪽 족윤적 이미지 높이 꽉 | 「사건 정보, 현장 이미지 정보는 탭으로 좌우 이동하고 세로 꽉」 「소제목 디자인 바꿔」 |

### 3-2. 이미지 편집
| 결정 | 근거 |
|---|---|
| 1차 편집만(2차 뷰어는 정밀 대조 몫). 도구 칸(아이콘 타일) · 작업대(보기 · 회전 막대 / 지금 도구 + 설정 + 취소 · 확인 · 저장 / 캔버스 / 빠른 보정) | 「각각 기능들 좀더 잘 드러나게」 |
| 오른쪽 = **편집 이력만**(AI 제안 없음). 줄마다 그 단계 모습 작은 그림, 누르면 작업대 위 미리보기 · 여기까지 되돌리기 | 「편집 이력만 남겨 AI 제안 빼 … 편집 이력은 당연 미리보기 가능해야하고. 각각 리스트마다」 |

### 3-3. 문양 코드
| 결정 | 근거 |
|---|---|
| AI 는 문양 추출(제안 + 확신도)만. AI 검색 방식 같은 AI 조건 없음 | 「AI 조건은 빼 … AI 기능은 여기서 문양 추출밖에 없지 않아??」 |
| 현장 이미지: 보기 조정(대비 · 밝기 · 반전 · 이진화, 보기용) · 확대경(크기 조절, 최소 48) · 더블 클릭 = 크게 살펴보기 · 확대 보기 칸(확대경 자리 ↔ 마우스 올린 문양 나란히, 고정) | 「마우스 대면 확대 … 원의 크기는 늘릴 수 있고 … 더블 클릭하면 새로운 편집 창 … 대비, 확대 등등」 「확대경이랑 옆에 문양을 두고 딱 비교」 |
| 4부위(상 · 중 · 하 · 윤곽) 카드: 코드 글자 없음(마우스 설명), 게이지 없음, AI 점수 크게, 가중치 = 그림 오른쪽 낮 · 보 · 높, 필수 = 진한 테 + 좌상단 표식 | 「문양 넘버 필요없고, 오른쪽 차트는 왜 … 가중치 설정하는거 문양 오른쪽 … 게이지 이런거 다 버려」 「필수는 테두리를 좀 더 찐하게 … 좌상단」 「×0.5는 뭐야? 빼. ai 점수는 중요」 |
| 문양 목록(윤곽 포함 8종): 종류 알약 탭 + 큰 타일 격자, 코드 찾기 없음 | 「전체 문양 리스트 … 원래 있었잖아 … 윤곽도 있어」 「탭으로 컴팩트하고, 코드 찾기는 필요없어」 |
| **룰베이스 가중치**(스펙 `2026-11-17-pattern-weight-rule-design.md`) | 「우리는 가중치 기능 없는데, 룰베이스로 가중치 기능 너가 넣어야해. 이건 스펙에 써라」 |
| 검색 이력: 한 줄 = 검색 한 번(넣은 문양 실제 그림 · 필수 · 가중치 · 결과 상위 신발 · 점수), 자세히 → 검색 결과 탭 | 「어떤 문양 모양으로 어떤 가중치 … 어떤 결과 … 자세히 누르면 검색결과」 |

### 3-4. 검색 결과
| 결정 | 근거 |
|---|---|
| AI 먼저 보기 상자 없음 → 순위 한 목록(내림차순), 보기 1 · 3 · 5개, 카드 = 점수 크게 + 부위 일치 표식 | 「그냥 순위가 쭉 … 1개 3개 5개 … 점수 … 어느 문양 일치하는지 살짝 상단」 |
| 화류번호 검색 · 유사도 필터 없음. 본 것/안 본 것 · 확인대상 유지 | 「화류번호 검색 이런거 빼. 유사도 필터도 빼고 … 본 것 안 본 것은 좋네」 |
| 자동 = 목록이 실제로 스크롤(속도 또는 n초 쪽 넘김 설정), 누르면 멈춤 | 「자동 누르면 자동 스크롤 … 클릭해서 멈추는 거고. 속도로 … 페이지 넘김으로 초」 |
| 마우스 올림 빠른 비교(현장 · 후보 · 부위 점수 · 고른 문양) | 「마우스 올렸을때 빠른 비교로 현재 선택한 문양이랑」 |

### 3-5. 정밀 대조
| 결정 | 근거 |
|---|---|
| 자동/수동 · 대응 목록 · 정보 탭 없음. 칸마다 보기 조정(대비 · 반전 · 회전 · 이진화), 확대 찍기로 양쪽 같은 부위 함께 확대(핀), 상 · 중 · 하(+윤곽) 고른 문양 비교 띠, AI 대조는 종합 · 부위 점수 · 한 줄 의견 | 「자동 수동이 왜 있어 … 대비 반전 회전 이진화 그리고 확대 찍어서, 중지하고, 거기랑 옆에 신발 어느 부위를 같이 확대 … AI 대조 … 컴팩트 … 대응 목록 빼. 정보도 … 상중하 나뉘어서 서로 선택한 문양 비교」 |

## 4. 신발 DB
| 결정 | 근거 |
|---|---|
| 패널 안 중복 제목 · 큰 조회 양식 · 자동/수동 · 엑셀 없음, 칩 + 필터 한 줄 | 「신발도 내가 말한거 동일. 신발도 자동 이런 건 없어도 되고」 |
| 신발 편집 = 한 화면(기본정보 줄 + 먹색 작업판: 밑창 원본/Shoerinsics · 보기 조정 · 확대경 · AI 문양 추출 → 4부위 수동 입력 → 문양 목록 + 확대 보기 칸), 문양 코드 탭과 같은 공용 부품(`entities/pattern/ui`) | 「기본정보 · 문양정보 이건 묶는게 … 하나로 등록」 「기존 컴포넌트들 활용 … 컴팩트」 「슈링식스 이진화, 확대 대비 반전 … 상중하 … 수동으로」 |
