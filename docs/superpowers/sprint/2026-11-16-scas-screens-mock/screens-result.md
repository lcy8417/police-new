## r2 — 「전부 시안 그대로」 (2026-11-16, R5)

공통: 위젯마다 `showPlus?: boolean`(기본 true) 하나로 +α · 실증 요소를 숨기고 감싼 요소에 `data-plus`. +α 값은 위젯 prop 한 묶음(`insight`)으로 받고(지금 서버 응답에 없는 값), 저장되는 값(S05 확인대상 ★ · S07 결과확인완료 · 교차 검증자)은 제어형 prop + 콜백. 동작 없는 새 버튼은 `onPlusAction(글자)` → 진열 페이지 `toast("시안 — 기능 준비 중", { description })`. 역할: 시안 `data-role`/`data-lock` → 위젯 안 `model/roles.ts`(`analyst` = EXAM_DECIDE, `verifier` = REPORT_APPROVE 이고 EXAM_DECIDE 없음, `investigator` = CASE_STATUS_VIEW 이고 CRIME_SEARCH 없음, S07 교차 검증 = CROSS_REVIEW, 관리자는 시안 CSS 처럼 모든 역할 줄을 봄). 위젯 사이 가져오기 금지라 세 위젯에 같은 파일을 하나씩 둠. 움직임은 모두 `motion-safe:`(ScanOverlay 길이만 시안대로 `motion-safe:[animation-duration:…]`), 움직임 줄이기면 막대는 목표 폭 · 훑기 선은 안 보임. 공유 파일 변경 · 새 공용 부품 요청: 없음.

## r3 — 편의(필터 · 보기 개수 · 자동 모드) (2026-11-16, T4)

설계서 §14-5 · 6 · 7. r3 편의는 +α 가 아니다 — `?plus=0` 에서도 보이고 `data-plus` 를 달지 않는다. 다만 +α 값이 있어야 뜻이 있는 칩(S05 본 것 · 확인대상 · AI 10건, S07 감정불능 · AI 추천과 다름)은 +α 를 켤 때만 보인다. 값(보기 개수 · 필터 · 검색 글자 · 이동 방식 · 간격 · 재생 · 초점 · 지금 후보)은 모두 위젯 props(제어형), 진열 페이지가 들고 보기 개수 · 썸네일 · 간격 · 필터는 화면별로 localStorage 에 기억(`scas-dev:sNN:*`, 읽기 · 쓰기 try/catch · 모양 검사, 깨지면 기본값). 자동 모드 · 검색 글자는 기억하지 않는다(다시 열 때 저절로 넘어가지 않게). 바꾸는 콜백을 넘기지 않으면 그 조작은 안 보인다(운영 연결 때 콜백을 넘기며 켠다).

| 기능 | 자리 · 동작 |
|---|---|
| 비교 1:1 · 1:3 · 1:5 | 버튼 줄 위 편의 줄 `ViewCountSwitch` 「비교」. 1:1 = 2차 PairStage(대응점 선 · 박스 · 대응 목록) 그대로. 1:3 · 1:5 = `MultiStage` — 현장(유류) 1장 + 지금 후보부터 n장(끝에서는 마지막 n장, `model/stage.ts candidateWindow`), 지금 후보 파란 테 · 「지금 후보」, 칸을 누르면 그 후보로. 보기 방식(RGB · 스케치)은 함께 |
| 후보 넘기기 | 후보 목록(`candidates` — 진열은 S05 가짜 1쪽 20건, 주소 신발이 없으면 맨 앞)이 있으면 SCAS 「이전 · 다음」이 켜져 앞뒤 후보로(처음 · 끝에서 꺼짐), ← → 키도 같음. `AutoPlayControl` 「후보 넘기기」 — n초마다 다음 후보, 마지막에서 멈춤, Space, 비교 그림 위 마우스 = 잠시 멈춤. 정렬 설정 창이 열렸거나 글자 입력 중이면 키를 듣지 않는다 |

- 지금 후보는 진열 페이지 상태(첫 값만 `?ftwr` · `?rank`) — 자동 넘김마다 주소 기록을 쌓지 않으려고. 1:1 발견 이미지는 지금 후보 그림(첫 후보는 2차와 같은 그림). 대응점 · +α 정밀 대조 값은 가짜라 후보가 바뀌어도 같다.
